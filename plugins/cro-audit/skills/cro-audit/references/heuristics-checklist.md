# Heuristic checklist

Check the page against the rows for its type. Mark a row only from what you saw, quote the
element, and name the principle. Heuristics are expert judgement, not behavioural evidence:
write "likely friction", never "loses sales". Principle names: **NN** = Nielsen Norman Group's
10 usability heuristics, **Baymard-style** = common checkout and form friction findings,
**Practice** = widely used CRO practice (a rule of thumb, not research).

## Every page

| # | Check | Principle |
|---|---|---|
| E1 | One clear primary action for the page's conversion; secondary actions visibly weaker | NN: aesthetic and minimalist design |
| E2 | The primary action is visible in the first screen on desktop and phone without scrolling | Practice |
| E3 | The value proposition (what it is, who for, why here) is readable in the first screen | NN: match with the real world |
| E4 | Price, or how pricing works, is visible without clicking, hovering or opening a form | Baymard-style: surprise costs and hidden info |
| E5 | What is included and what happens next after the action is stated near the action | NN: visibility of system status |
| E6 | Competing calls to action in the same view (more than one equal-weight primary) | NN: minimalist design |
| E7 | Button and link labels say the outcome ("Book a consultation"), not "Submit" or "Learn more" only | NN: match with the real world |
| E8 | Trust evidence near the decision point (real reviews with source, credentials, guarantees, policies), not only in a distant band | Practice |
| E9 | Social proof is specific and attributable, not generic quotes with no name or source | Practice |
| E10 | Claims that need a source have one on the page ("no source on the page" goes to fact-check) | Practice |
| E11 | Navigation offers a way out and a way back; no dead ends | NN: user control and freedom |
| E12 | Header and menu do not pull attention from the primary action on conversion pages | Practice |
| E13 | Popups, banners and chat widgets do not cover the primary action or content on load | NN: user control |
| E14 | Urgency or scarcity messages are true and checkable | Practice (and consumer law) |
| E15 | Contact options and policies (shipping, returns, cancellation) are findable in one step | NN: help and documentation |

## Forms and booking

| # | Check | Principle |
|---|---|---|
| F1 | Field count: ask only what is needed to act now; count required vs optional | Baymard-style form friction |
| F2 | Required fields are marked; optional ones say so | NN: error prevention |
| F3 | Labels sit outside the field and stay visible while typing, not placeholder-only | Baymard-style |
| F4 | Input types fit the data (email, tel, date pickers) and autofill works | Baymard-style |
| F5 | Errors are shown at the field, in plain words, and say how to fix | NN: help users recover from errors |
| F6 | Multi-step flows show progress and let the person go back without losing entries | NN: visibility, user control |
| F7 | Reassurance at the commit point: what happens next, response time, no obligation, privacy | Practice |
| F8 | No account required to complete the main action | Baymard-style |

Do not submit forms to test errors. Judge from the visible markup and labels, and say that
error handling was not exercised if you could not see it.

## Product page

| # | Check | Principle |
|---|---|---|
| P1 | Title, price, variant choice and add-to-cart in one view | Practice |
| P2 | Variant selection states are obvious; unavailable options are shown as such | NN: visibility of system status |
| P3 | Images show the product at scale, in use, and from more than one angle | Baymard-style |
| P4 | Shipping cost and time, returns and stock are visible before the cart | Baymard-style: surprise costs |
| P5 | Key details (ingredients, size, materials, how to use) are readable without hunting through tabs | Practice |
| P6 | Reviews show count, average and a way to read them, tied to this product | Practice |

## Collection or listing page

| # | Check | Principle |
|---|---|---|
| C1 | Product cards show name, price and a clear image; the click target is obvious | Practice |
| C2 | Filtering and sorting are usable and show how many results remain | Baymard-style |
| C3 | An empty or filtered-out state explains and offers a way back | NN: error recovery |

## Homepage

| # | Check | Principle |
|---|---|---|
| H1 | A visitor can tell what the business is and who it is for in five seconds | Practice |
| H2 | The route to the main conversion is one click from the first screen | Practice |
| H3 | Image or carousel bands do not push the primary action below several screens | Practice |
| H4 | Carousels do not auto-advance past content before it can be read | NN: user control |

## Booking, consultation or service page

| # | Check | Principle |
|---|---|---|
| S1 | The next step ("Book", "Request a consultation") repeats at natural stopping points | Practice |
| S2 | Who does the service, where, how long, and what to expect are stated | Baymard-style: hidden info |
| S3 | Price or price range, or why it is quote-only, is stated | Baymard-style |
| S4 | Before and after, results or proof are real, labelled and not overstated (send to fact-check) | Practice |

Skip rows that do not apply to the page type and say which you skipped.
