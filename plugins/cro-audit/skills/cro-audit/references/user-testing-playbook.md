# User testing (stream 7)

Watching a few real people try to do the key task shows problems no dashboard can. The skill can't
recruit or run sessions; it writes the plan and the script, and analyses the notes or recordings
the person brings. Tag findings `[Test]` and say how many people and of what kind.

## Plan

- **The task comes from the conversion goal**: book a consultation, find and buy a specific product,
  find the price of a treatment. Write two to four tasks, each as a situation, not an instruction.
- **Participants**: about **five per distinct audience** (for example first-time visitors, existing
  customers) is the usual working size for finding the major problems; run another small round after
  fixes rather than one big round. Recruit people who match the real audience, not colleagues.
- **Format**: moderated (you can ask why) or unmoderated (cheaper, no follow-up). Use phone for
  mobile tasks, because behaviour differs.
- **Don't test your own opinions**: don't hint, don't explain the page, and don't ask "do you like it?".

## Script

1. Welcome: "We're testing the website, not you. There are no wrong answers. Please think aloud."
2. Warm-up: how they would normally find a [provider/product like this].
3. Tasks, one at a time, written as a scenario: "You've heard about [treatment/product] and want to
   know if it's right for you and what it costs. Show me how you'd find out." Don't name buttons.
4. After each task: "What did you expect to happen? Was anything unclear?"
5. Close: "What would make you more (or less) likely to book or buy?" and "Anything that surprised you?"

## Notes to capture

For each task and person: did they finish, how long, where they hesitated or went the wrong way, what
they said aloud, and what they expected versus found. Record the quote and the moment.

## Rate each problem

Use the Nielsen Norman severity scale: 0 not a problem, 1 cosmetic, 2 minor, 3 major, 4 blocks the task.
Count how many participants hit it. A severity 3 or 4 problem seen by two or more people is a priority.

## Write-up

A table of problems: what happened, who, how many, severity, the page element involved, and a
suggested fix. Link each to the analytics leak or heuristic finding it explains. Remember it is five
or so people: report counts, not percentages.
